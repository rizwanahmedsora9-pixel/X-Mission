RNS Gateway v7.1 — Clock-based expiry, kick vs ban
==================================================

Problems reported on v7 (Magisk module, real phone)
  1. A 1-hour voucher behaved like "60 minutes of use": a customer who
     used 3 minutes a day could stretch it for a month.
  2. When a voucher ran out the phone did not get the captive sign-in
     page back, so a new voucher could not be entered.
  3. A kicked device showed "disconnected by staff" forever and could
     not redeem a new voucher.

What was wrong
  • Expiry was always stored as an absolute time (activated + seconds),
    but ENFORCEMENT lived only in the 15-second supervisor loop. If that
    loop died, or its unlocked rewrite raced a redeem, the device kept its
    firewall allow indefinitely. An "active" row with a blank expiry was
    also treated as "allowed forever".
  • On expiry the phone was deauthed BEFORE its allow rule was removed, so
    its reconnect probe escaped to the internet and Android marked the
    network "validated" — no sign-in sheet.
  • "Kick" wrote a permanent client state that blocked every future redeem,
    exactly like a ban.

Fixes
  • Wall-clock expiry, enforced three ways
      - supervisor sweep (now under the store lock, no race)
      - rns-expire.sh fired by the page shell whenever an unpaid device
        probes (rate-limited), independent of the supervisor
      - page-shell watchdog restarts rnsd.sh if it is dead
    An active row with no expiry is repaired (activation + seconds) and
    never allowed through; an active row with no device is reset to new.
  • Order on expiry / kick / ban: remove firewall rules → kill conntrack
    flows → disassociate + deauthenticate (all known hostapd_cli and ctrl
    paths) so the phone reconnects and its captive probe hits the portal.
  • Kick / Unkick = pause and resume. Kick takes the device offline at once
    (portal shows again) but leaves its voucher clock running. Unkick puts
    it back on the same voucher; a NEW valid code (counter or online) also
    re-admits it, ending the paused voucher and clearing the mark. A
    wrong/dead code changes nothing.
  • Online payment Tracking ID. /api/pay/init issues a single-use
    RNS-XXXXXX reference bound to device+package+wallet (2 h). The portal
    shows it with Copy and tells the customer to write it in the wallet
    notes; the TID submission must quote it or nothing is activated. Shown
    under the TID in Payments, printed on the receipt, in payrefs.tsv.
  • Ban = blocked (counter and online) until Unban. Unban leaves no stale
    row; ban/unban cycles work repeatedly.
  • Portal: exact "Expires at" time, live countdown against the server
    clock, auto-return to the code form when time is up, and a reason line
    (time over / ended by staff / blocked) via /api/me.
  • Staff panel: Codes tab shows "till <date time>"; Clients tab shows the
    end time, Kick/Ban with hints, Clear for kicked, Unban for banned.
  • CLI: rns-ctl.sh clients | kick | unkick | ban | unban | expire

RNS Gateway v7 — Online Payment Gateway
========================================

What's new
  • JazzCash / EasyPaisa auto-payment on the captive portal
  • Customer pays → enters TID → system validates format + amount match
    → internet activates INSTANTLY → voucher PDF downloads
  • No admin intervention needed (auto-verify ON by default)
  • Dedicated Online Packages builder (separate from counter packages)
  • Payments tab in staff panel for auditing and manual overrides
  • TID validation: JazzCash 8-12 digits, EasyPaisa 8-15 digits
  • Duplicate TID rejection, rate limiting, full audit trail

Setup
  1. Flash the zip
  2. Settings → Payment gateway → enter your JazzCash/EasyPaisa numbers
  3. Settings → Online packages → build packages for online sales
  4. Done — Buy Online appears on the captive portal

Files changed since v6
  module/rns/bin/store.sh      — payment store, TID validation, auto-verify
  module/rns/bin/rns-http.sh   — payment API endpoints, auto-verify handler
  module/rns/bin/rns-ctl.sh    — payments/pay-confirm/pay-reject CLI
  module/rns/www/portal.html   — Buy Online tab + payment flow + PDF download
  module/rns/www/admin.html    — Payments tab + Online Packages builder
  module/OPERATOR.txt          — v7 operator notes
  PLAN.md                      — full technical documentation
  README.md                    — updated with payment gateway section
