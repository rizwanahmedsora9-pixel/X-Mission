RNS Gateway 7.1 — shop phone operator notes
============================================

What changed in 7.1 (time, kick, ban)
  Voucher time is by the CLOCK, not by use.
    A 1 Hour code entered at 1:00 PM ends at 2:00 PM. It does not matter
    if the customer browsed for 3 minutes or 60 — the time runs from the
    moment the code is typed. The customer's page and your Codes tab both
    show the exact end time ("till 26 Sep 14:00").
    Behind the scenes the gateway now enforces this three ways: the
    15-second supervisor sweep, a check every time an unpaid phone touches
    the sign-in page, and a watchdog that restarts the supervisor if it is
    ever found dead. A code can no longer run on past its hour.
  When the time ends the phone is sent back to the sign-in page.
    The gate rules for that phone are removed FIRST, then the phone is
    dropped off the hotspot so it reconnects and Android shows "Sign in to
    network" again. The customer types the next code and carries on.
  Kick ≠ Ban.
    Kick   ends the customer's current session right now. It is NOT a
           block: the same phone can enter a new voucher immediately and
           the panel shows it as active again. Use it for "change phones",
           "time's up early", or to force a fresh sign-in.
    Ban    blocks the phone. No voucher (counter or online) works on it
           until you press Unban. Unban restores normal service; you can
           ban and unban as often as you need.
    Clear  (shown on a kicked device) just removes the "kicked" label; the
           customer's next code does that by itself anyway.
  Command line:
    rns-ctl.sh clients            devices, state, voucher, exact end time
    rns-ctl.sh kick <mac>         end session now (new code works at once)
    rns-ctl.sh ban <mac>          block until unban
    rns-ctl.sh unban <mac>        allow again
    rns-ctl.sh expire             enforce expiry right now (same as sweep)


This module is for YOUR hotspot on this rooted phone. It does not join
other networks, it does not collect Wi-Fi passwords, and it does not
decrypt HTTPS. Customers only type a voucher code.

Install
  Magisk → Modules → Install from storage → RNS_Gateway.zip → Reboot.
  Same module id as before (RNS_Hotspot), so this replaces the old module.

Open the staff panel
  Magisk → RNS Gateway → Action. It waits for the listener and opens the
  browser as phone user 0. If Android does not launch a browser, open:
  http://127.0.0.1:8080/admin
  First launch asks you to create a password. Write it down.
  v5 opens the panel on THIS phone no matter which listener is serving:
  the page shell now reads the connection's own address from /proc, so the
  old "Staff only — open this page on the shop phone" answer on your own
  screen is fixed. If the compiled listener cannot start on this phone, v5
  records that (busybox-nc engine) and automatically upgrades to the real
  listener later — the panel keeps working either way.
  If you ever see "gateway functions are not answering yet", the pages are
  fine — the rest of the gateway is still recovering. Refresh in a moment.

Customer sign-in notification
  v5 keeps the captive redirect installed at all times. Earlier versions
  rebuilt the firewall by wiping and re-adding it every pass; for a short
  moment a customer's probe could escape to the real internet, the phone
  marked the network "verified", and the sign-in notification never came.
  The gate is now updated rule by rule and the redirect is never missing.
  The module also finds the hotspot interface by itself (ap0 / softap0 /
  swlan0) in case a ROM names it differently.
  Join RNS, wait for the "Sign in to network" notification, and tap it.
  If the sheet was already dismissed on that phone, FORGET the network on
  that phone, then join again — Android remembers an old "verified" result.
  Do not use an HTTPS URL: this module rejects guest TCP 443 instead of
  pretending to be a TLS site.

Build your packages first (nothing is preset)
  Gateway 6.0 ships with NO packages at all. You make every one yourself, so
  the Sell tab only ever shows what you actually sell.
  Staff panel → Settings → Package builder:
    Name          what the customer sees, e.g. "Fast Hour"
    Speed DL      download speed in Kbps (2048 = 2 Mbps)
    Speed UL      upload speed in Kbps
    Time          a number, then pick Hours or Days  (3 + Hours, 2 + Days)
    Price         a number, then pick "per hour" or "per day"
    Total price   fills in itself from Time x Price. You can still type your
                  own number over it — whatever is in that box is what the
                  slip prints and what the sales report counts.
  Examples: 3 + Hours at 50 per hour = Rs 150.  2 + Days at 300 per day = Rs 600.
  Each saved package gets an Edit and a Delete button under the form.
  If you upgraded from v5, your seven old stock packages (1 Hour, 3 Hours,
  6 Hours, 12 Hours, 1 Day, 7 Days, 30 Days) are still there — v6 never
  deletes an existing shop's packages. Delete the ones you do not want.

Sell internet
  1. Turn the Android hotspot ON (the module renames it to RNS, channel 6, open).
  2. Build at least one package (above). Without one, Sell has nothing to show.
  3. Staff panel → Sell → tap a package. Generate up to 100 codes at once.
  4. Read the code to the customer.
  5. Customer joins Wi-Fi "RNS" (no password). The sign-in page opens.
  6. They type the code. That phone is unlocked until the time ends.
  One code = one phone. Kick or Unbind from the panel if they change phones.

Sales report — how many you sold, and for how much
  Staff panel → Sales. Pick a date range (or tap Today / Yesterday / Last 7
  days / Last 30 days / This month) and you get:
    Codes generated   how many you made in that range  +  rupee total
    Codes redeemed    how many customers actually used +  rupee total
    By day            one row per date
    By package        one row per package
  Generated minus redeemed is your unsold stock. Rupees are added in paisa as
  whole numbers, so a long month does not drift by a rupee.
  Export CSV writes a spreadsheet file of the same range.
  Two honest gaps are printed on the report instead of being hidden:
    - codes with no price (revenue is understated by that many codes)
    - older codes from before v6 that have no sale date (not counted)
  Command line, same numbers:
    su -c 'sh /data/adb/modules/RNS_Hotspot/rns/bin/rns-ctl.sh sales'
    su -c 'sh /data/adb/modules/RNS_Hotspot/rns/bin/rns-ctl.sh sales 2026-09-01 2026-09-26'
    su -c 'sh /data/adb/modules/RNS_Hotspot/rns/bin/rns-ctl.sh packages'

If clients have no internet and no sign-in page
  su -c 'sh /data/adb/modules/RNS_Hotspot/rns/bin/rns-ctl.sh verify'
  v6's verify shows which listener is running, whether the panel opens on
  this phone, the actual firewall rules, the detected hotspot interface,
  your package list, today's sales totals, and the last page requests (a
  customer's probe lands in that list when it reaches the phone — if the
  list stays empty while a phone is connected, the problem is below the
  page shell).
  Paste that output back. Log is also /data/local/tmp/rns_hotspot.log and
  /data/local/tmp/rns_pages.log.

Pause the gate (everyone gets through, for debugging only)
  su -c 'sh /data/adb/modules/RNS_Hotspot/rns/bin/rns-ctl.sh pause'

Uninstall
  Remove the module in Magisk and reboot. Vouchers stay in /data/adb/rns.
  To delete them too, create /data/adb/rns/PURGE before uninstalling.


RNS Gateway 7.0 — Online Payment Gateway (JazzCash / EasyPaisa)
=================================================================

Customers without a paper voucher can now pay via JazzCash or EasyPaisa
directly from the captive portal. TID is auto-verified and internet
activates instantly — no admin touching anything.

Setup (one time)
  Staff panel → Settings → Payment gateway:
    JazzCash number     your JazzCash mobile number (e.g. 03001234567)
    JazzCash name       account holder name (shown to customer)
    EasyPaisa number    your EasyPaisa mobile number
    EasyPaisa name      account holder name (shown to customer)
  At least ONE number must be set for Buy Online to appear on the portal.

  Staff panel → Settings → Online packages:
    Build packages SPECIFICALLY for online sales. These are separate from
    counter packages — set their own names, speeds, durations and prices.
    At least ONE online package must exist for Buy Online to appear.
    Examples: "Student Hour" Rs 30, "Night Owl 6h" Rs 100, "Weekend Day" Rs 200

  Auto-verify checkbox:
    Settings → Payment gateway → "Auto-verify payments" (ON by default).
    When ON: customer enters TID → system validates format + amount →
    instant activation + PDF download. No admin needed.
    When OFF: every payment waits for staff to manually confirm.

How a customer pays online
  1. Customer joins Wi-Fi RNS → captive portal opens.
  2. Taps "Buy Online" tab (next to voucher entry).
  3. Picks a package from the grid.
  4. Chooses JazzCash or EasyPaisa → sees your number and account name.
  5. Sends the exact amount from their phone.
  6. Enters the TID from their payment SMS.
  7. System auto-verifies:
       ✓ TID format valid (JazzCash: 8-12 digits, EasyPaisa: 8-15 digits)
       ✓ TID not already used
       ✓ Amount matches the package price
  8. ALL checks pass → internet activates INSTANTLY.
  9. Voucher PDF receipt downloads automatically.
  No admin intervention needed.

TID validation rules
  JazzCash    8 to 12 numeric digits
  EasyPaisa   8 to 15 numeric digits
  Minimum     6 characters
  Maximum     20 characters
  Duplicates  same TID rejected across ALL records (any customer, any time)
  Rate limit  max 5 attempts per device per 10 minutes

If auto-verify fails
  Invalid TID format  → customer sees "check TID from your payment SMS"
  Duplicate TID       → "This Transaction ID was already used"
  Rate limited        → "Too many attempts. Please wait."
  Customer can retry with the correct TID.

Payments tab (staff panel)
  New "Payments" tab shows ALL online payment records:
    Time · Customer (MAC + IP) · Package · Method · TID · Amount · Status
  Filter: All / Pending / Confirmed / Rejected.
  Auto-confirmed payments show "confirmed" with "auto-verified" in the note.
  Manual confirm/reject buttons are available for PAY_AUTO_VERIFY=0 mode.
  You can revoke any voucher later if you spot a fake TID.

PDF voucher receipt
  When payment is confirmed, a PDF downloads with:
    Shop name, voucher code, package, duration, speed, price,
    payment method, Transaction ID, MAC address, IP address.
  Customer keeps this as proof. Download is restricted to the paying device
  or the local admin panel.

Counter packages vs Online packages
  Counter packages (Settings → Package builder → Sell tab):
    These are for YOUR use at the counter. Generate voucher slips, hand
    them to customers. Never shown on the captive portal.
  Online packages (Settings → Online packages):
    These are the ONLY packages customers see on Buy Online. Completely
    separate catalogue with its own names, speeds, durations and prices.
    You can charge different prices for online vs counter if you want.

Online payments in the sales report
  Auto-confirmed vouchers are tagged "online <TID>" in the note field.
  They appear in the sales report alongside counter vouchers.
  The generated/redeemed counts and rupee totals include both types.

Command line
  su -c 'sh .../rns-ctl.sh payments'          list all payment records
  su -c 'sh .../rns-ctl.sh pay-confirm PAY-X' confirm manually
  su -c 'sh .../rns-ctl.sh pay-reject PAY-X'  reject manually
  su -c 'sh .../rns-ctl.sh verify'            now shows payment summary

Config (config.env)
  JAZZCASH_NUMBER=     your JazzCash mobile number
  JAZZCASH_NAME=       account holder name
  EASYPAISA_NUMBER=    your EasyPaisa mobile number
  EASYPAISA_NAME=      account holder name
  PAY_AUTO_VERIFY=1    1 = auto-verify (default), 0 = manual confirm

Data files
  payments.tsv          16 columns per payment record
  online-packages.tsv   same layout as packages.tsv, for online packages only
